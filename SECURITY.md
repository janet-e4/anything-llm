# Security Policy — E4 Studios fork of AnythingLLM

This document covers the security posture of the E4 deployment at https://zhealth.lvbs.com. For upstream AnythingLLM security disclosures, see [Mintplex-Labs/anything-llm](https://github.com/Mintplex-Labs/anything-llm/security).

---

## Secrets management

All secrets live in `~/.openclaw/anythingllm/.env` (gitignored) or under `~/.openclaw/anythingllm/storage/` (bind-mounted, also gitignored). Nothing sensitive is baked into images or committed to the repo.

| Secret | Location | How it's generated | Rotation impact |
|---|---|---|---|
| `JWT_SECRET` | `.env` | `openssl rand -hex 32` (256-bit hex) | Invalidates all active sessions. Users must log in again; passwords are unaffected. |
| `GENERIC_OPEN_AI_API_KEY` (OpenClaw bearer token) | `.env` | Sourced from `~/.openclaw/openclaw.json` | Container must be restarted. No user impact unless OpenClaw itself rotates the token. |
| Database encryption key | `storage/comkey/` (auto-generated on first boot) | Generated by AnythingLLM internals | **Do not rotate.** Encrypted columns in `anythingllm.db` become unreadable without the original key. |
| Push notification VAPID keys | `storage/push-notifications/` (auto-generated) | Generated by AnythingLLM internals | Subscribers must re-subscribe. |
| Cloudflare tunnel credentials | `~/.cloudflared/<tunnel-id>.json` | Created by `cloudflared tunnel create` | Requires re-running `cloudflared tunnel route dns ...`. |
| User passwords | `users.password` column in `anythingllm.db` | bcrypt-hashed by AnythingLLM | Admin can reset via Settings -> Users. |

> Note: AnythingLLM 1.12.1 does **not** use `SIG_KEY` / `SIG_SALT` variables, and they are not present in this deployment's `.env`. Earlier versions of this doc listed them in error.

### Generating fresh secrets

```bash
openssl rand -hex 32                # JWT_SECRET
```

After editing `.env`:

```bash
cd ~/.openclaw/anythingllm && docker compose restart anythingllm
```

## Telemetry

AnythingLLM upstream sends anonymous usage events to PostHog by default, gated on the `DISABLE_TELEMETRY` env var. This fork disables telemetry **at two layers**:

1. **Environment flag** — `DISABLE_TELEMETRY=true` may be set in `.env` (optional, see below).
2. **Forced at startup** — the patched `server/index.js` (bind-mounted from `~/.openclaw/anythingllm/server-index.js`) sets `process.env.DISABLE_TELEMETRY = "true"` as its first executable statement, before any application module loads. This means telemetry is off **even if `.env` does not set it** — the env var is forced true in-process. Upstream's telemetry code is still present in the image but never fires because every call site checks `DISABLE_TELEMETRY`.

The "Anonymous Telemetry" toggle has also been removed from the Privacy & Data section of the UI in `e4/ui-customizations` so it can't be re-enabled accidentally.

To verify telemetry is off:

```bash
# The patched entry file forces the flag:
docker exec anythingllm sh -c "grep -n 'DISABLE_TELEMETRY' /app/server/index.js"
# expected: a line near the top -> process.env.DISABLE_TELEMETRY = "true";
```

Note: grepping for `posthog` in the image will still return hits — the upstream telemetry module ships in the image unchanged. The fork's defense is forcing the gate flag, not removing the PostHog code.

## User authentication

- **Password storage:** bcrypt-hashed in the `users.password` column. The plaintext password is never stored or logged.
- **Multi-user mode:** enabled. Role-based access — `admin` users see all workspaces and settings; `default` users only see workspaces they're explicitly granted access to.
- **Password reset:** admin-only. There is no email-based password reset flow because the deployment has no outbound SMTP configured. An admin (`jeremy` or `nick`) resets passwords via Settings -> Users.
- **Session tokens:** JWT signed with `JWT_SECRET`. Rotating the secret kicks everyone out.
- **No SSO** is configured. All access is username/password through the AnythingLLM UI.

Current accounts and roles are documented in `~/.openclaw/anythingllm/UPGRADING.md` (gitignored).

## Network exposure

| Surface | Binding | Exposure |
|---|---|---|
| AnythingLLM container | `127.0.0.1:3001` -> container `3001` | Host-only. Not reachable from the LAN. |
| OpenClaw gateway | `127.0.0.1:18789` | Host-only. Reached from the container as `host.docker.internal:18789` via the Docker Desktop Mac bridge. |
| Qdrant | `127.0.0.1:6333` | Host-only. Reached from the container as `host.docker.internal:6333`. |
| Public URL | Cloudflare tunnel `zhealth-allm` | Outbound-only tunnel from `cloudflared` to Cloudflare's edge. No inbound ports opened on the host. |

The Cloudflare tunnel performs TLS termination at Cloudflare. The connection from Cloudflare to the local `cloudflared` process is over QUIC/HTTP3; the hop from `cloudflared` to `localhost:3001` is plain HTTP on loopback.

Cloudflare Access policies on `zhealth.lvbs.com` should be configured to gate the application behind email auth — verify in the Cloudflare Zero Trust dashboard.

## Files containing secrets — NEVER COMMIT

The following paths must never be added to git, copied to public locations, or sent over email/Slack:

- `~/.openclaw/anythingllm/.env`
- `~/.openclaw/anythingllm/storage/anythingllm.db` (contains bcrypt password hashes plus all chat history)
- `~/.openclaw/anythingllm/storage/comkey/` (DB encryption key)
- `~/.openclaw/anythingllm/storage/push-notifications/` (VAPID keys)
- `~/.cloudflared/cert.pem`
- `~/.cloudflared/*.json` (tunnel credentials)
- `~/.openclaw/openclaw.json` (OpenClaw bearer token + provider keys)

`.gitignore` in this repo covers the in-repo cases. The OpenClaw / Cloudflare paths are outside the repo by design.

If a secret is accidentally committed:

1. Rotate the secret immediately (regenerate the JWT secret, revoke the OpenClaw token, etc.).
2. Remove it from history with `git filter-repo` and force-push.
3. Notify janet@e4lv.com so the rotation can be coordinated with the deployment.

## Staying current with upstream security fixes

This fork is an independent project. It diverged from upstream AnythingLLM at commit **`b1e5b6f`** (v1.12.1) and does not chase upstream `master` for features. It does, however, remain exposed to any vulnerability that exists in the v1.12.1 baseline or in its dependency tree, so the fork actively monitors upstream for **security-relevant** changes:

- **Upstream GitHub Security Advisories** — https://github.com/Mintplex-Labs/anything-llm/security/advisories
- **Dependabot alerts** — dependency vulnerabilities flagged on the fork repo and cross-referenced against upstream.
- **Upstream releases** — https://github.com/Mintplex-Labs/anything-llm/releases, scanned for security fixes between v1.12.1 and the current upstream tip.

When a security fix is identified as applicable to the fork's `b1e5b6f` baseline, it is merged through the branch stack (`master` → `feature/message-draft-autosave` → `e4/ui-customizations`) and a new image is deployed.

This evaluate-and-merge process is **documented and automated as a dedicated skill + agent**, kept on the maintainer's desktop at `~/Desktop/anythingllm-fork-maintenance/` (operational tooling, deliberately not committed to this repo). The branch/rebase mechanics it drives are in [CONTRIBUTING.md](./CONTRIBUTING.md#rebasing-on-upstream) and [UPGRADING.md](./UPGRADING.md).

**Divergence baseline for security tracking:** `b1e5b6f961ed88c6d0f6f55186f4734ed3cd9439` — AnythingLLM v1.12.1.

## Reporting security issues

- Email **janet@e4lv.com** with details and a reproduction if possible.
- **Do not open public GitHub issues for security problems** — the fork is public and any disclosure there is immediately visible.
- For vulnerabilities in upstream AnythingLLM (not fork-specific), follow Mintplex Labs' security policy at https://github.com/Mintplex-Labs/anything-llm/security.

Acknowledgement of receipt: within 2 business days. Initial assessment: within 7 business days.
